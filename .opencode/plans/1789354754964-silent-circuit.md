# Plan: Add a comprehensive Security Policy and GitHub security configurations

## 1. Overview
The goal is to provide users and contributors with a clear security policy and to automate security checks using GitHub.

## 2. Files to Create / Modify

| File | Purpose |
|------|--------|
| `.github/SECURITY.md` | Main security policy document. |
| `.github/CODEOWNERS` | Assign owners for PR reviews and code owners for security. |
| `.github/codeql.yml` | Enable CodeQL analysis for the repo. |
| `.github/secret-scanning.yml` (optional) | Enable GitHub secret scanning. |

## 3. SECURITY.md Contents

*Supported Versions* – list supported plugin versions.
*Reporting a Vulnerability* – provide an email address (e.g., security@github.com or a direct issue link) and a timeline for response.
*Known Vulnerabilities* – reference the Dependabot process.
*License & Legal* – brief statement.

## 4. CODEOWNERS
Create entries that map directories (`src/`, `scripts/`, `.github/`) to maintainers – e.g., `* @ubahmapk`.

## 5. CodeQL
Use the following minimal configuration:
```
queries: .github/codeql-queries/
```
Add a set of default queries for JavaScript/TypeScript.

## 6. Testing and Verification
1. Commit and push the new files.
2. Verify that GitHub displays *Security* tab.
3. Ensure Dependabot PRs trigger a *Security* review.
4. Run `npm run lint` and `npm test` locally.

## 7. Next Steps
After pushing, the policy will be visible in the repository sidebar.
